## 1. 移行の概要

### 現行設計から新設計へ

| 項目 | 現行 | 新設計 |
|------|------|--------|
| データ管理 | git + Profile | スナップショット（フォルダコピー） |
| ユーザー概念 | ブランチ、断面 | 環境スナップショット |
| 状態表示 | 不明瞭 | 常時表示 |
| 操作 | 複雑 | ワンクリック |

### なぜ移行するのか

1. **シンプルさ**: git の知識がなくても誰でも使える
2. **分かりやすさ**: 今どの環境で遊んでいるか一目で分かる
3. **かんたん操作**: ワンクリックで保存・復元・切替

### 移行のメリット

**ユーザーにとって**
- 学習コストが下がる（git を理解する必要がない）
- 操作ミスが減る
- 状態が把握しやすい

**開発者にとって**
- コードがシンプルになる
- バグが減る
- 保守しやすくなる

## 3. Phase 2: スナップショット機能の実装

### 目的

新しい「環境スナップショット」機能を実装し、現行システムと並行して動かす。

### スナップショットの保存方式：フォルダコピー方式

**採用理由**
- 最もシンプル
- 実装が容易
- デバッグが容易

**仕組み**
```
~/.catalyzer/
├── current/              # 現在の作業環境
│   ├── mods/
│   ├── config/
│   └── saves/
│
└── snapshots/            # 保存されたスナップショット
    ├── stable-0i-jp/     # スナップショット1（フォルダごとコピー）
    │   ├── snapshot.yaml # メタ情報
    │   ├── mods/
    │   ├── config/
    │   └── saves/
    │
    └── experimental-dev/ # スナップショット2
        ├── snapshot.yaml
        ├── mods/
        ├── config/
        └── saves/
```

### メタ情報ファイル（snapshot.yaml）

```yaml
name: "Stable 0.I + 日本語Mod"
created_at: "2026-01-27T10:00:00Z"
game_version: "cdda-0.I-2026-01-20-1811"
platform: "macos"
description: "安定版で日本語化Modを入れた構成"
```

### 容量対策（将来のオプション機能）

フォルダコピー方式はディスク容量を多く使うため、以下の対策を将来実装する：

| 機能 | 説明 | 優先度 |
|------|------|--------|
| 古いスナップショットの自動削除 | 設定した数を超えたら古い順に削除 | 中 |
| 使用容量の警告表示 | 総容量が閾値を超えたら警告 | 中 |
| 手動クリーンアップ | 不要なスナップショットを選んで削除 | 低 |
| 容量表示 | 各スナップショットの容量を一覧表示 | 低 |

### 並行稼働期間の設計

```
Phase 2 開始
    │
    ├─ 新規ユーザー → スナップショット機能を使用
    │
    ├─ 既存ユーザー
    │   ├─ 現行機能（git + Profile）を継続使用可能
    │   └─ 希望すればスナップショットに移行
    │
    └─ 移行ツール提供
        └─ Profile → Snapshot 変換機能
```

### 実装する機能

| 機能 | 説明 |
|------|------|
| スナップショット保存 | 現在の環境をフォルダごとコピーして保存 |
| スナップショット復元 | 保存した環境を current にコピーして復元 |
| 環境切替 | スナップショット間をワンクリックで切替 |
| 状態表示 | ヘッダーに現在の環境名を常時表示 |
| かんたん編集 | Mod の追加/削除をシンプルな操作で |

## 4. Phase 3: git 機能の段階的廃止

### 目的

git 機能を完全に廃止し、ユーザー画面から git の概念を消す。

### ステップ 1: git を内部実装に隠蔽

| 対象 | 現状 | 変更後 |
|------|------|--------|
| 画面表示 | 「ブランチ」と表示 | 「環境」と表示 |
| 操作 | git 操作ボタンがある | スナップショット操作のみ |
| エラーメッセージ | git 用語を含む | 一般的な表現に |

### ステップ 2: 画面から git 概念を削除

- [ ] 「ブランチ」という言葉を削除
- [ ] 「コミット」という言葉を削除
- [ ] git 関連のボタン/メニューを削除
- [ ] git 関連の設定項目を削除

### ステップ 3: 内部実装のリファクタリング

- [ ] git 依存コードを分離
- [ ] フォルダコピー方式に完全移行
- [ ] git2 クレートへの依存を削除（オプション）

### 廃止対象の機能

| 機能 | 現在の場所 | 廃止方法 |
|------|------------|----------|
| ブランチ作成 | columns.tsx | スナップショット複製に置換 |
| ブランチ切替 | columns.tsx | スナップショット切替に置換 |
| プルリベース | release.rs | 削除 |
| git clone | release.rs | 不要（ls-remote のみ使用） |
| 断面管理 | profile/mod.rs | スナップショットに統合 |

### 完了条件

- [ ] ユーザー画面に git 用語がない
- [ ] git 操作が画面からできない
- [ ] 既存ユーザーのデータ移行が完了
- [ ] git の知識なしで全機能が使える

## 5. 後方互換性

### 既存ユーザーデータの移行

#### 移行対象

| データ | 場所 | 移行方法 |
|--------|------|----------|
| Profile 設定 | `~/.catalyzer/profiles/` | 自動変換 |
| Mod 構成 | 各 Profile 内 | スナップショットへコピー |
| 設定ファイル | 各 Profile 内 | スナップショットへコピー |
| セーブデータ | 各 Profile 内 | スナップショットへコピー |

#### 自動移行と手動移行

| 方式 | メリット | デメリット | いつ使う |
|------|----------|------------|----------|
| 自動移行 | ユーザーの手間なし | 予期せぬ問題のリスク | 通常はこちら |
| 手動移行 | ユーザーが制御できる | 手間がかかる | 複雑なケース |

#### 推奨する移行フロー

```
アプリ起動
    │
    ├─ 旧データを検出
    │   │
    │   └─ 移行ダイアログを表示
    │       │
    │       ├─「自動で移行」→ バックアップ作成 → 自動変換
    │       │
    │       └─「手動で行う」→ 移行ガイドを表示
    │
    └─ 移行完了後
        └─ 新しい画面で操作開始
```

### エラー時の対応

| エラー種別 | 対応 |
|------------|------|
| 変換失敗 | 元データを保持、ログ出力、サポート案内 |
| 部分的失敗 | 成功分は移行、失敗分を報告 |
| ディスク容量不足 | 事前チェック、警告表示 |

### バックアップ方針

- 移行前に自動でバックアップを作成
- バックアップ場所: `~/.catalyzer/backup/{タイムスタンプ}/`
- 保持期間: 30日（設定で変更可能）

## 6. リスクと対策

### データ損失リスク

| リスク | 発生条件 | 対策 |
|--------|----------|------|
| 移行中のクラッシュ | アプリ異常終了 | トランザクション的な移行処理 |
| バックアップ失敗 | ディスク容量不足 | 事前に容量チェック |
| 変換ロジックのバグ | コードミス | 十分なテスト、段階的ロールアウト |

### ユーザー混乱リスク

| リスク | 発生条件 | 対策 |
|--------|----------|------|
| 新しい画面の使い方が分からない | UI 変更 | チュートリアル、ヘルプ整備 |
| 前の機能が見つからない | 機能廃止 | 移行ガイド、FAQ |
| 移行タイミングが分からない | 告知不足 | アプリ内通知、リリースノート |

### 技術的リスク

| リスク | 発生条件 | 対策 |
|--------|----------|------|
| パフォーマンス低下 | 新実装の非効率 | ベンチマーク、最適化 |
| 互換性の問題 | OS/環境による違い | 複数環境でテスト |
| ライブラリの問題 | アップデート | 依存の最小化、バージョン固定 |

### 対策の優先順位

1. **必須**: 自動バックアップ、移行前チェック
2. **重要**: 段階的ロールアウト、ロールバック機能
3. **推奨**: チュートリアル、ヘルプ整備
